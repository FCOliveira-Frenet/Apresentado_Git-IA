Por que Git é importante?

Git é o sistema de controle de versão que registra a evolução de arquivos e permite que pessoas trabalhem juntas com histórico, comparação e recuperação de mudanças.

Git e GitHub: funções diferentes

  • Git: ferramenta distribuída de versionamento. Registra commits, branches e merges localmente.
  • GitHub: serviço remoto para hospedar repositórios Git e colaborar com issues, pull requests, revisão, automações e releases.
  • É possível usar Git sem GitHub; GitHub usa Git e adiciona colaboração e serviços ao redor do repositório.

O que fica registrado

Commits guardam um conjunto de alterações com autor, data, mensagem e ligação com o histórico anterior. Branches permitem desenvolver uma mudança em paralelo; merge reúne o trabalho depois da revisão.

git status git diff git add src/arquivo.js git commit -m "fix: corrige validação do formulário" git log --oneline

Dependências: o que Git faz e o que não faz

Git versiona arquivos que descrevem dependências, como package.json, package-lock.json, requirements.txt ou pyproject.toml. Quem baixa e instala pacotes é o gerenciador do ecossistema, como npm, pip ou Poetry.

Manifestos e lockfiles ajudam a equipe a reproduzir versões compatíveis. Pastas instaladas, como node_modules, normalmente são regeneradas e ficam fora do Git pelo .gitignore.

Valor para o time e o dia a dia

  • Divide o trabalho em branches por tarefa, sem sobrescrever diretamente o trabalho alheio.
  • Usa pull requests para discutir diffs, solicitar revisão e registrar decisões.
  • Identifica quando e por que algo mudou e facilita investigar regressões.
  • Permite comparar versões, recuperar mudanças e preparar releases com mais confiança.
  • Ajuda no onboarding: integrantes consultam código, histórico, documentação e issues.

Mais que código; não é backup completo

O repositório pode guardar documentação, testes, scripts, configurações e diagramas relevantes. README e histórico reduzem a dependência de conhecimento informal.

Um clone remoto ajuda a recuperar o repositório, mas não substitui backup de bancos de dados, arquivos ignorados ou artefatos externos. Segredos, credenciais e dados pessoais não devem ser publicados.

O que significa IA + Git

Git mantém o histórico confiável; uma ferramenta de IA pode ajudar a compreender e modificar o projeto. São funções complementares: IA não é controle de versão e Git não gera respostas inteligentes.

Como a IA pode apoiar o fluxo

  • Explicar arquivos, arquitetura, mensagens de erro e diffs.
  • Propor uma implementação em uma branch, mantendo mudanças revisáveis.
  • Sugerir testes, documentação e mensagens para commits ou pull requests.
  • Resumir histórico relevante ou ajudar a investigar uma regressão.
Princípio de trabalho

IA sugere; Git registra; o time decide.

Revise o diff, rode testes e confirme os comandos antes de commitar ou enviar. A aprovação e o merge seguem as regras definidas pela equipe.

git status git diff # analisar sugestões da IA git diff --check # testar antes de criar o commit

Limite desta demonstração

Esta aula explica o conceito e os cuidados de IA + Git, mas não conecta a página a um modelo de IA. As consultas são feitas em uma ferramenta autorizada separadamente; nunca envie chaves, tokens, senhas ou conteúdo confidencial sem permissão.

Git no fluxo diário de uma equipe

O fluxo combina rastreabilidade local no Git com colaboração e revisão no GitHub.

01

Planejar e atualizar

Registre o trabalho em uma issue ou tarefa, atualize sua cópia local e crie uma branch para manter a mudança isolada.

git switch main git pull --ff-only origin main git switch -c feat/minha-tarefa
02

Fazer mudanças pequenas e verificáveis

Edite código, documentação ou testes. Confira o estado e o diff para confirmar que só os arquivos pretendidos serão registrados.

git status git diff git add caminho/do/arquivo git diff --staged
03

Registrar e compartilhar

Crie commits com mensagens claras e envie sua branch remota. O histórico mostra o que mudou e permite que outras pessoas busquem a branch.

git commit -m "feat: adiciona filtro por status" git push -u origin feat/minha-tarefa
04

Revisar em pull request

Abra um pull request, explique objetivo e testes, peça revisão e discuta o diff. Checks automáticos podem rodar antes de aprovar.

05

Integrar e manter o histórico

Depois de revisão e validações, faça merge segundo as regras do time. Atualize a branch local e prepare releases quando necessário.

Onde a IA pode entrar

Em qualquer etapa, um assistente pode explicar comandos e diffs, sugerir testes ou ajudar a redigir uma descrição de pull request. A equipe continua responsável por revisar, executar e aprovar as mudanças.

Skills e automações

Skills são capacidades especializadas que a IA pode usar conforme o objetivo da tarefa. Elas tornam o agente mais preciso e útil no projeto.

  • Revisão de código e padrões de qualidade.
  • Criação de documentação técnica e onboarding.
  • Refatoração e organização da arquitetura.
  • Fluxo de testes, validação e deploy seguro.

Exemplo prático

Uma skill pode ser usada para analisar o projeto, apontar riscos e preparar um resumo claro para a equipe.

Prompt: "Analise este repositório, identifique riscos de manutenção, sugira melhorias de UX e gere um README com instruções de instalação e uso."

O que instalar e preparar

  • Git: instalado e disponível no terminal (Git Bash, PowerShell ou terminal do VS Code).
  • Editor: VS Code ou outro editor com integração de IA compatível.
  • Assistente de IA: extensão ou agente autorizado, conta ativa e acesso habilitado pela organização.
  • GitHub: conta com acesso ao repositório e autenticação configurada.
  • Ferramentas do projeto: runtime e dependências exigidos pelo repositório, por exemplo Node.js ou Python quando aplicável.

Os recursos, limites e automações disponíveis variam conforme o produto de IA, o plano contratado e as políticas da organização.

Formas de integrar a IA

  • No editor: extensão ou agente com acesso ao workspace aberto; ideal para consultas e mudanças locais revisáveis.
  • No GitHub: agente de codificação autorizado no repositório, sujeito às permissões e regras da organização.
  • Em automações: workflows e APIs podem chamar serviços de IA usando secrets protegidos, permissões mínimas e revisão apropriada.

Esses modos são diferentes: abrir o repositório com um assistente no editor não concede automaticamente acesso remoto nem permissão para fazer push.

API de IA: conceito para a aula

Nesta apresentação, o uso de API é explicado apenas como conceito. Não há chat, chamadas reais ou respostas simuladas; não é necessário criar chave nem instalar um backend para acompanhar a demonstração.

Em um projeto real, o frontend enviaria a pergunta para um backend protegido, que chamaria o provedor de IA. A chave ficaria somente como segredo no servidor — nunca em HTML, JavaScript público ou commits.

Configuração inicial do Git

Configure a identidade que ficará registrada nos commits e confirme que o repositório remoto aponta para o projeto correto.

git --version git config --global user.name "Seu nome" git config --global user.email "seu-email@exemplo.com" git config --global init.defaultBranch main git remote -v

Autentique-se no GitHub pelo fluxo oficial do editor, pelo Git Credential Manager ou com SSH. Opcionalmente, instale o GitHub CLI e use gh auth login. Nunca coloque senha ou token diretamente em comandos, prompts ou arquivos versionados.

Trazer um repositório existente

git clone https://github.com/organizacao/repositorio.git cd repositorio git status git pull --rebase origin main

Se o projeto já está no computador, abra a pasta raiz no editor e valide o remoto com git remote -v.

Comandos do ciclo com IA

Peça à IA para explicar o estado e sugerir o próximo passo; confira o resultado no terminal antes de confirmar.

git status git diff git diff --staged git add caminho/do/arquivo git commit -m "feat: descreve a mudança" git push -u origin nome-da-branch
  • status/diff: entender exatamente o que mudou.
  • add/commit: selecionar e registrar mudanças revisadas.
  • push: enviar a branch para o remoto.
  • pull/fetch: atualizar ou inspecionar mudanças remotas.

Trabalho seguro em branch e PR

git switch -c feat/minha-alteracao git fetch origin git pull --rebase origin main git push -u origin feat/minha-alteracao

Abra um pull request no GitHub, descreva objetivo, testes e riscos, peça revisão e faça merge conforme as regras do repositório.

Arquivos locais e segredos

Inclua no .gitignore dependências, builds, logs e arquivos locais; não versione .env com credenciais. Compartilhe apenas um .env.example sem valores secretos.

# .gitignore .env .env.* !.env.example node_modules/ dist/

Como fazer consultas úteis à IA

Informe o objetivo, o contexto, os arquivos relevantes, as restrições e como validar o resultado. Peça primeiro análise e plano quando a tarefa for grande.

"Analise o estado atual com git status e git diff. Explique as mudanças sem editar nada. Depois proponha um plano. Não inclua .env, tokens ou dados pessoais. Ao terminar, liste os arquivos alterados, os testes executados e os comandos Git sugeridos. Não faça push nem merge sem minha confirmação."

Boas consultas: “resuma este diff para uma PR”, “explique este conflito sem resolvê-lo ainda”, “sugira testes para esta alteração” ou “prepare uma mensagem de commit; mostre-a antes de executar”.

Permissões e o que é permitido

  • Sugerir melhorias em código, documentação e processo.
  • Gerar contextos, resumos e explicações sobre o projeto.
  • Ajudar na preparação de commits e pull requests.
  • Reforçar produtividade e revisão ajustada ao contexto.

O que exige controle humano

  • Tokens, credenciais e chaves de acesso.
  • Arquivos .env e dados sensíveis.
  • Decisões de merge, deploy e liberação.
  • Conteúdo crítico do produto e estratégia da entrega.

Se um segredo for enviado ao Git, removê-lo do arquivo não basta: revogue ou troque a credencial e siga o procedimento de resposta a incidentes da equipe.

Estrutura recomendada para uso profissional

Quando bem guiada, a IA acelera o projeto sem ignorar regras de segurança, qualidade e responsabilidade.

01

Contexto do projeto

O agente precisa compreender a intenção, a arquitetura e o padrão do repositório para agir bem.

02

Objetivo claro

Defina o que precisa ser entregue, qual problema será resolvido e qual resultado esperado.

03

Validação humana

A revisão do time garante que a solução siga direção certa, qualidade e segurança.

04

Commit, merge e publicação

Com a validação concluída, a entrega entra no fluxo de GitHub com rastreabilidade e contexto.
